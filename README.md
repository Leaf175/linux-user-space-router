# Linux 用户态软路由（AF_PACKET 原始套接字）

在 Linux 上不依赖内核转发，用 C 语言从链路层抓包、自己维护 ARP 缓存、自己做跨网段转发，
并带一个能持久化的 IP 过滤防火墙。目标是**复刻一台实体路由器最小可用的工作流程**。

## 背景

`PF_PACKET / SOCK_RAW` 让进程可以绕过 TCP/IP 协议栈直接收发链路层帧。本项目用它实现了：

- 链路层帧的收发与解析（以太网头 + ARP + IPv4）
- 一张自己维护的 ARP 缓存表（不用系统的那张）
- 一次完整的「收帧 → 判网段 → 选出口 → 改 MAC → 发出」转发流程
- 一个能落盘持久化的目的 IP 过滤防火墙

## 功能

| 类别 | 内容 |
|---|---|
| 接口管理 | `ioctl` 获取本机所有网卡的 IP / 掩码 / 广播地址 / MAC，作为转发出口依据 |
| ARP | 双向链表维护 IP↔MAC；表项缺失时构造 ARP 广播（最多重试 3 次）并回填应答；带超时老化 |
| 转发 | 解析 IPv4 目的地址，按网段匹配选出出口网卡，改写以太网头的源/目的 MAC 后发出 |
| 过滤 | 独立键盘线程增删过滤 IP，命中的报文直接丢弃；规则写入 `ip_config`，启动时自动加载 |
| 并发 | 收包主循环 + 键盘线程 + 每包派生的 ARP / IP 处理线程 |
| 构建 | Makefile 统一管理，模块按职责解耦（接口 / 链表 / 处理线程 / 主流程） |

## 架构

```
                      ┌────────────────────────┐
   eth0 ◄────────────►│  收包主循环 (PF_PACKET) │◄────────────► eth1
                      └───────────┬────────────┘
                                  │ 按以太网类型分派 (0x0806 / 0x0800)
                 ARP 帧 ──────────┼────────── IPv4 帧
                        ┌─────────▼────────┐   ┌─────────▼────────┐
                        │   arp_pthread    │   │    ip_pthread    │
                        │  学习 IP→MAC      │   │  查目的网段/改MAC │
                        └─────────┬────────┘   └─────────┬────────┘
                                  ▼                      ▼
                          ARP 缓存链表             IP 过滤规则链表
                        (双向, 超时老化)           (命中即丢)
                                  ▲                      ▲
                        ┌─────────┴──────────────────────┴────────┐
                        │            key_pthread（终端交互）        │
                        └─────────────────────────────────────────┘
```

转发的关键一步：**IP 层不变，MAC 层逐跳变化**。源/目的 IP 保证端到端寻址，
源/目的 MAC 保证每一跳的下一台设备能收下这一帧。

## 目录结构

| 文件 | 职责 |
|---|---|
| `main.c` | 主流程：读配置 → 初始化接口 → 建线程 → 收包分派 |
| `main.h` | 全局套接字、收包缓冲结构体 `RECV_DATA` |
| `get_interface.c/.h` | `ioctl` 采集各网卡 IP/MAC/掩码，按网段选出口 |
| `arp_link.c/.h` | ARP 缓存表（双向链表 + 老化） |
| `ip_link.c/.h` | 过滤规则链表（增删查 / 落盘 / 加载） |
| `arp_pthread.c/.h` | ARP 报文处理：学习源 IP→MAC |
| `ip_pthread.c/.h` | IPv4 报文转发：选出口、查/建 ARP、改写 MAC、发出 |
| `key_pthread.c/.h` | 终端交互：增删过滤 IP、查看链表 |
| `Makefile` | 编译 |

## 编译

```bash
make            # 生成可执行文件 router
make debug      # -O0 -g -fsanitize=address
make clean
```

## 运行

需要 root（或 `CAP_NET_RAW`），并且**关掉内核转发**，否则内核会抢在用户态程序之前处理报文：

```bash
sudo sysctl -w net.ipv4.ip_forward=0
sudo ./router
```

实验拓扑：一台 Linux 虚拟机挂两块网卡（分别接两个网段）+ 一块开发板作为对端主机。

## 配置

过滤规则保存在 `ip_config`（程序首次运行时自动创建，退出前回写）。
**不要手工编辑这个文件**，规则请通过程序内的终端菜单增删；它已被 `.gitignore` 排除。

## 验证

| 项目 | 方法 | 结果 |
|---|---|---|
| 跨网段连通 | `ping -c 2000 <对端IP>` | 2000 包 0 丢包，平均 RTT 0.6 ms |
| MAC 逐跳改写 | `sudo tcpdump -ne -i eth0 icmp`、`-i eth1 icmp` | 进入/离开两端的源、目的 MAC 均被正确替换 |
| 过滤生效 | 加入某个 IP → 再 ping | 该 IP 的报文被丢弃，其余不受影响 |
| 规则持久化 | 增规则 → 重启程序 | 规则仍在，无需重新配置 |

复现方式见左列命令。吞吐量可以用 `iperf3 -u` 自行测（转发逻辑不区分为 TCP 还是 UDP），
不过线程模型是「每包起一个线程」，高 pps 下会成为瓶颈，测出来的数字仅供参考。

## 已知限制与改进方向

1. **不递减 TTL、不重算 IP 首部校验和**：报文原样转发，严格意义上不符合 IPv4 路由器的行为；
   多跳级联时无法靠 TTL 终止环路，因此代码里用「目的地址广播不转发」「出口为 lo 不转发」做了兜底。
2. **每包一个线程**：收包后按帧类型 `pthread_create`，高频小包下线程创建开销明显；
   改进方向是线程池，或单一 worker + 队列。
3. **没有路由表**：只做直连网段匹配，不支持按下一跳查表与多级级联。
4. **过滤粒度只到目的 IP**：尚未支持端口 / 协议 / 关键字过滤。
5. 广播判断只看了目的地址第 4 字节是否为 255，对非 /24 网段不严谨。
